# dsh-pptx-annotate 简介

**一句话**：把 DSH 右侧的 PPT 预览，从「只能看」变成「能批注、能交付」。

它是 DSH 的一个文档预览器插件。装好后，`.pptx` 在右侧面板里不再是一张只读的 PDF，
而是一页页可以点击的幻灯片：点中哪个元素，意见就挂在哪个元素上，
一键提交后，Agent 收到的是一条能精确定位的修改清单。

---

## 1. 它要解决的问题

DSH 内置的 Office 预览走的是 `pptx → PDF → 渲染` 这条路：**看得见，动不了**。

所以改一份 PPT 的真实动作是：

> 看一眼 → 记住「第 2 页那个大标题」→ 切到对话 → 用文字描述位置 → Agent 猜你指哪个 → 改错 → 再来一轮

这个插件把「用文字描述位置」这一步删掉了。位置不再靠说，靠点。

## 2. 结构：什么在哪里

```
┌──────────────────────── 浏览器（Client 半边）────────────────────────┐
│  lib/client.js                                                       │
│                                                                      │
│  ① 工具栏        文件名 · 批注数 · 第 N 页 · 「发送给 Agent」          │
│  ② 左侧目录      缩略图列表，面板 ≥520px 才出现，可滚动跳转            │
│  ③ 页面区        每页 PNG + 一层透明的元素热区                         │
│  ④ 底部批注区    点选后的意见输入框，可删可改                          │
│  ⑤ 输入框旁      「N 条批注处理中…」（composer.dock 座位）             │
└───────────────┬──────────────────────────────────────────────────────┘
                │ fetch /api/pptx-annotate/*
┌───────────────▼──────────── Host 半边（lib/index.js）────────────────┐
│  GET /deck      → src/pptx-geom.js  解 ZIP + 读 XML + 算盒 → JSON      │
│  GET /slide     → src/render.js     子进程调 LibreOffice Kit → PNG     │
│  GET /version   → stat().mtimeMs    只做 stat，用来判断「改完没有」     │
└──────────────────────────────────────────────────────────────────────┘
                │
                ▼
        conversation.send(prompt)  →  主对话里的一条普通 user turn
```

每个文件干什么：

| 文件 | 职责 | 依赖 |
|---|---|---|
| `lib/index.js` | Host 入口，注册三条鉴权路由 | `node:fs` |
| `lib/client.js` | 浏览器入口，注册预览器 + 批注界面 + 进度条 | 只有 `react` |
| `src/zip.js` | 读 ZIP 中央目录，只支持 stored / deflate | `node:zlib` |
| `src/xml.js` | 轻量 XML 读取器（PPTX 是机器生成的良构 XML） | 无 |
| `src/pptx-geom.js` | 形状树 → 归一化坐标盒；组合变换展开；占位符从 layout/master 继承位置 | 无 |
| `src/render.js` | 调捆绑的 LibreOffice Kit 渲染 PNG，按文件版本缓存 | `node:child_process` |

**零第三方运行时依赖**——`client.js` 手写成 DSH 的 `window.__ModuleLoader__.load({ factory })` 格式，
只 `require("react")` 这一个平台种子；Host 侧只用 Node 内置模块。

## 3. 四个关键设计决策

**① 几何在 Host 算，UI 在 Client 画。**
浏览器只拿到「第几页、哪些盒子、什么文字」，完全不需要理解 OOXML，也不需要把 pptx 传进浏览器。
好处是解析逻辑可以用 Node 直接单元测试，且大文件不会撑爆前端内存。

**② 用 `priority: 'extension'` 并列注册，而不是改内置预览。**
`ctx.documentPreviews.register({ extensions: ['pptx'], priority: 'extension' })` 会排在内置实现之前，
所以默认接管；但工具栏下拉里内置预览仍然在，随时能切回去。**不做替换，做并列**——
升级 DSH 不会把我的改动冲掉，我也不用碰签名过的应用包。

**③ 命中规则：文字优先，同组取面积最小。**
PPT 里装饰色块常常压在文字下面，如果按「最后绘制的元素优先」，点标题很容易选中它背后的框。
现在的规则是：先在命中的元素里挑带文字的，再挑其中面积最小的。点大标题，拿到的就是标题本身。

**④ 刷新靠文件版本，不靠超时。**
提交后每 2 秒 `stat` 一次文件，mtime 一变就重拉几何、并把图片 URL 换成 `&v=<mtime>`。
URL 变了，浏览器缓存自然失效——这比「猜 Agent 什么时候改完」可靠得多。

## 4. 和原生预览的功能对比

| 能力 | 原生 Office 预览 | dsh-pptx-annotate |
|---|---|---|
| 打开 `.pptx` | ✅ 转 PDF，只读 | ✅ 直接渲染每页 |
| 选中单个元素 | ❌ 只有一整页 | ✅ 形状树解析（组合展开、占位符继承） |
| 逐元素批注 | ❌ | ✅ 点元素 → 写意见 → 编号标记 |
| 批注回到对话 | ❌ 手打文字描述 | ✅ 一键提交为结构化 prompt |
| 改完回看 | ❌ 手动刷新 | ✅ 轮询文件版本，自动换图 |
| 目录 / 缩略图 | ❌ | ✅ 面板够宽时自动出现，可滚动跳转 |
| 提交进度 | ❌ | ✅ 输入框旁「N 条批注处理中…」 |
| 命中歧义 | — | ✅ 文字优先，点标题不会点到背后的框 |
| 随时退回 | — | ✅ 工具栏下拉切回原生预览 |
| 适用范围 | 所有 Office 格式 | 仅 `.pptx` |

**真正的差别不是功能数量，而是「谁来决定改哪里」。**
没有插件时，改哪里由 Agent 从你的文字里猜；有插件时，改哪里由你的鼠标决定，歧义从源头消失。

## 5. 代价与边界

- **只接管 `.pptx`**：`.ppt` / `.docx` 仍然走原生预览
- **首次打开约 10 秒**：LibreOffice 冷启动，之后同文件毫秒级
- **批注不落盘**：发送后清空，刻意为之，避免下次打开看到过期意见
- **文本框溢出误差**：几何来自 shape 的声明尺寸，文字跑出文本框时热区会略小于视觉范围
- **进度提示的结束信号是文件变化**：如果你只提问不改稿，提示会挂到 10 分钟超时
- **依赖内部 slot 契约**：DSH 大版本升级可能需要跟着调整

## 6. 怎么用

```text
① 右侧预览里点元素      → 元素高亮 + 编号
② 输入意见              → 「标题太大，缩到 40pt」
③ 点「发送给 Agent」    → 结构化条目进入当前会话，输入框旁出现「N 条处理中」
④ Agent 逐条改          → 每条回一行 ✅ 第 X 页 · 元素：改了什么
⑤ 文件一变              → 预览自动换图，进度提示消失
```
